# Matrix discrepancies

Per spec/spec.md §5.4: `usecase-component-matrix.json` (IG1228 chapter 2, corpus-level) and
each use case's own `links.components` (that document's own References section) are two
independent sources for the same fact. Where they agree, that's confirmation. Where they
don't, it's signal worth keeping, not a conflict to silently resolve one way or the other —
logged here per task 3.3, generated by cross-checking all six pilot use cases (see
`tools/extract_usecase_matrix.py`'s output vs. each `knowledge/use-cases/TMFSxxx/TMFSxxx.md`).

|---|---|---|---|

| TMFS031 | TMFC023, 028, 035 | same | ✅ |

## What each disagreement actually means

**TMFS009 — the matrix undershoots.** The document's own References section names seven
components; the matrix only credits three of them (TMFC013 Service Balance Management,
TMFC015 Service Usage Management, TMFC040 Product Usage Management — notably, the two
"not yet specified" ones from Phase 2, §5.2). TMFC001/002/005/008 (Product Catalog, Product
Order Capture, Product Inventory, Service Inventory) are missing from the corpus-level table
for this use case. IG1228's own version history records incremental "aligned chapter 2 to
IG1242 vXX.0" edits release over release — plausibly this use case's chapter-2 row hasn't
been revisited since an earlier, narrower version of its content.

**TMFS029 — the document undershoots, and this is the interesting one.** TMFS029's own
References section is a literature bibliography (IETF RFCs, other TM Forum IGs — see
spec/tasks.md 0.4's note on this), not a component/API list at all, so `docx2md.py` correctly
extracted nothing from it. But the corpus-level matrix *does* have an entry for TMFS029:
TMFC053 (Service Quality Management) and TMFC061 (Work Order Management). This is exactly
the scenario spec.md §5.4 was designed around — the two sources aren't redundant, they're
complementary, and relying on only one (the document itself) would have left this use case
with zero linked components despite IG1228 knowing better.

**TMFS030 — a single-component gap.** The document's References section names 14 components;
the matrix has all but TMFC006 (Service Catalog Management). Smallest discrepancy of the
three, consistent with the broader pattern already established in the research phase: TMFS030
is Beta/Member Evaluated, not yet fully settled, and single-field drift between a use case's
own content and the corpus index is exactly what "not yet GA" looks like in practice.

## What this means for consumers of `knowledge/`

A skill answering "what components does TMFS009 touch" gets a *different, real* answer
depending on which source it reads. Until this is reconciled at the source (which isn't this
repo's job — it's TM Forum's own chapter 2 vs. individual document maintenance process), a
skill that needs completeness should read **both** `links.components` and the matrix and take
the union, not either alone — and should say so if it's citing the union, since neither
source alone is the full picture for TMFS009/029/030.
