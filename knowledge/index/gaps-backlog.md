# Gaps backlog

Generated by running `skills/feedback-harvest-gaps-from-lessons-learned` (spec.md
§11.2) for real against the full 24-use-case corpus — task 9.4, not a
single-document dry run. Every use case's `## Lessons learned`/`## Impacts
identified` sections were read (21 of 24 carry both; TMFS009 has neither;
TMFS018 nests "Impacts identified" under "Lessons learned" rather than as
a sibling — all checked directly against the live corpus before writing
this, not assumed). Enhancement requests to existing APIs (the majority of
what's in these sections — field/attribute/operation additions, mostly
tracked as individual `AP-xxxx`/`ISA-xxxx` JIRA tickets) are deliberately
excluded per the skill's own Step 2 filter: this file is about capability
gaps — proposed components/APIs that don't exist at all yet — not a JIRA
export.

Cross-checked against `knowledge/index/components.json`/`apis.json` as of
this run (24 use cases, 31 components, 51 API versions, same corpus as
`spec/tasks.md` Phase 4). **Updated during a `decompose-requirement-against-oda`
pilot run (`spec/tasks-skills-consumer.md` Phase 1) that re-checked gap 3
directly against the live cached corpus**: gap 3 has since been resolved
(`TMFC012` now exposes `TMF716`) — the other four remain open as of this
update. Re-run this cross-check on every future refresh cycle — a gap here
can go stale exactly this way, the same lesson TMFS030 itself already
draws for one of its own smaller observations (a Product Configurator gap
resolved by TMFC027 v2.2.0, noted directly in that document's own text).

## Deliberately excluded from this backlog

The large majority of "Lessons learned"/"Impacts identified" content
across the corpus is enhancement requests to *existing* APIs — new
fields, new operations, clarified attributes — each usually its own
`AP-xxxx`/`ISA-xxxx` ticket. That's real, valuable feedback for API
maintainers, but it's evolution of something that already exists, not a
missing asset, and there are far too many individual instances across 21
documents to aggregate into one backlog without drowning the five genuine
new-capability gaps above in noise. If a consumer needs the full,
unfiltered list for a specific API, read that use case's own "Impacts
identified" section directly.
