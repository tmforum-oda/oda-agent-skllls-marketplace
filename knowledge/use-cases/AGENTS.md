# knowledge/use-cases/ — Agent Instructions

`TMFSxxx` — narrative ODA use cases (business scenario, sequence
diagrams, component/API integration), one folder per id:

```
knowledge/use-cases/{TMFSxxx}/{TMFSxxx}.md   frontmatter envelope + prose body
knowledge/use-cases/{TMFSxxx}/media/         diagrams referenced from the body
```

Converted from TM Forum's member-gated use-case DOCX files
(`tools/docx2md.py`) — see `spec/spec.md` §5.1/§5.1.1 for the conversion
rules and boilerplate-exclusion list.

## Before trusting a use case's content

1. **Check `status`/`maturity`/`approval_status`/`release_status` in
   frontmatter first.** A use case can be draft, pre-GA, or fully
   `GA`/`TM Forum Approved`/`Production` — these are independent fields
   (`spec.md` §5.4), not one flag. `skills/check-usecase-maturity/` exists
   specifically to turn this into a plain-language verdict — use it
   rather than re-deriving trust level yourself.
2. **`links.components`/`links.apis` are curated by TM Forum's own
   authors** — cite these ids when drafting requirements/tests/mocks
   against a use case, don't invent an integration point the use case
   doesn't itself name.
3. **Not every `TMFSxxx` id has a converted file here.**
   `knowledge/index/usecase-list.json` lists every id IG1228 knows about,
   including ones with nothing converted yet (`planned`/`not available`).
   An id missing under `use-cases/` is real, surveyed information, not a
   fetch failure — check that file before assuming a gap is a mistake.
4. **A use case's own "Lessons learned"/"Impacts identified" sections may
   flag a capability gap** (a proposed component/API that doesn't exist
   yet). Don't treat that as something to build here — check
   `knowledge/index/gaps-backlog.md` first; it's the consolidated,
   cross-checked view across every use case that raises the same gap.

## Provenance and regeneration

`{TMFSxxx}.md` is generated by `tools/docx2md.py` from
`references/use-cases/{TMFSxxx}/{TMFSxxx}_v{version}.docx` — don't
hand-edit the body or frontmatter; re-run the tool (assisted refresh
track, `spec.md` §6.1 — requires a logged-in TM Forum member session, not
schedulable). `media/` is enriched in place afterward by
`skills/process-usecase-media/` (renames raw images, writes PlantUML/text
sidecars) — that step *does* write here directly; everything else in this
subfolder is tool-generated.
