- [x] **5.1** Wrote `spec/refresh-runbook.md`: step-by-step assisted-track execution (check IG1228 version → regenerate the two IG1228-derived index files → diff the roster against what's converted → per-id download/convert/metadata loop → index regen → automated track → `refresh_report.py` → commit), plus the judgment calls Phase 1–4 already hit once (the TMFS019 stale-Production-link trap, the search-URL trick, naming conventions) so a second person doesn't have to re-derive them. - [x] **5.2** Wrote `tools/refresh_report.py`. Three index files, three key strategies: use-cases.json and components.json are keyed by `id` (their file gets overwritten in place on a version bump, so that's a *changed* row, not a new one); apis.json is keyed by `meta_path`, not `id` — multiple API versions genuinely coexist side by side (fetch_api.py's own docstring), so keying by id would make a new version look like a modification of the old one and silently hide that the old version is still cached too. Watches `version`/`status`/`maturity`/`approval_status`/`release_status` for use cases (spec.md §6.3's "maturity is a first-class signal" finding — a plain version-bump watch would miss a `Beta → GA` transition that doesn't happen to land on the same day as a version bump) and `version`/`status` for components/APIs. Appends a dated Markdown entry to `CHANGELOG.md` (creating it with a header on first run); if nothing changed, prints that and leaves `CHANGELOG.md` untouched rather than appending an empty entry every dry run.
