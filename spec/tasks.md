## Phase 2 — Linking: component and API specs

- [x] **2.1** Write `tools/fetch_component.py`, step one: build `knowledge/index/component-folder-map.json` from one tree listing at the pinned tag (spec.md §5.2.1). 35 components found.

  **A real infrastructure finding surfaced building this, worth knowing before running Phase 4/5 unattended:** `raw.githubusercontent.com` specifically (not `api.github.com`, not `github.com` — tested head to head) drops the connection outright with no response roughly 40–50% of the time on this network, repeatably across many trials. Plain `curl --retry` does **not** cover it (curl doesn't classify a dropped/empty response as one of its default transient codes) — `--retry-all-errors` does, verified 0/15 failures with it vs. ~40–50% without, and confirmed it does *not* waste time retrying a genuine fast 404 (0.19s, no retry) — only real connection failures. This lives in a new shared `tools/_http.py` (also worked around a separate, unrelated issue: this machine's Python `ssl`/`requests` stack fails local cert verification against these same hosts even though `curl` verifies them fine — `_http.py` shells out to `curl` for exactly that reason, not just for the retry logic).
- [x] **2.2** `fetch_component.py`, step two: fetch each component's spec YAML unmodified, write `component.meta.json` with `status` read straight out of `componentMetadata.status` (real values seen: `specified`, and one component reporting `Pre-production` — IG1242's vocabulary isn't perfectly uniform either, worth knowing). Not-yet-specified components get a meta-only record (`status: not_yet_specified`), no `component.yaml` — 2 of the 23 referenced components hit this (TMFC013, TMFC015), matching what IG1228's own inventory already said about them (Planned).
- [x] **2.3** Write `tools/fetch_api.py`: walks *all three* function blocks (`coreFunction`, `managementFunction`, `securityFunction`) × both API list keys (`exposedAPIs`, `dependentAPIs`) in a cached `component.yaml`, not just `coreFunction` — the task description undersold this; APIs are declared in all three. **Found and filtered a real upstream data-quality issue**: every single component.yaml checked has an unfilled Helm-template placeholder in `managementFunction` (`id: "exposedAPI_id"`, `url: "{{.Release.Name}}-{{.Values.component.name}}-sm"` — literal token names, not real values, apparently a metrics-scraping self-reference that never got filled in when these specs were generated). Filtered by id shape (`^TMF\d+$`) rather than trusted as data.
- [x] **2.4** Ran 2.1–2.3 against all 23 components / 50 unique API versions referenced by the six pilot use cases. 21/23 components specified, 2/23 not-yet-specified (expected). 49/50 API fetches succeeded; the one failure, `TMF641 v4.0.0`, is a **genuine broken link already in the upstream component spec** — a stale `/Beta/.../4.2.0/...` S3 path that 404s, referenced by two real components (TMFC003, TMFC007) with a real API id, not a fluke. Rather than let that be a silent gap, `fetch_api.py` now writes a `status: fetch_failed` meta record (mirroring `not_yet_specified`'s pattern) so it's a visible fact in the data layer, not just a line that scrolled past in a log. `validate_envelope.py --strict` passes clean across both `knowledge/components/` (23) and `knowledge/apis/` (50, including the failure record).
- [x] **2.5** Already done — `tools/docx2md.py`'s parse-then-discard step from task 0.4 *is* this automation; nothing further needed. (0.4's implementation is the search-based parser, not the strict-format one originally sketched in this task's description — see 0.4's notes on why.)
- [x] **2.6** Optional enrichment, built and run. `gh auth token` piped into `curl` confirmed real, working access to the private `tmforum-rand/OAS_Open_API_And_Data_Model` repo in this environment. `tools/fetch_api_samples.py` lists that repo's `apis/` folder once (same map-then-fetch shape as 2.1/2.2, cached as `knowledge/index/api-samples-folder-map.json`), and for each already-cached API pulls whatever version folder exists there (the dev repo mostly tracks Gen5-in-progress; our cached specs are mostly Gen4, so exact version numbers don't usually match, and the script doesn't insist on one) — fails closed per-API on any error, never blocks the run.

  **Two real bugs found and fixed on the first run, both worth knowing about:** (a) GitHub's Contents API `download_url` field carries a signed, apparently short-lived/single-use token for a private repo — fetching it directly failed with `SSL_CONNECT_ERROR` on roughly a third of files, and retrying the *same* signed URL didn't help (consistent with single-use). Fixed by fetching file content through the same authenticated Contents API call already proven reliable (`Accept: application/vnd.github.raw` + our own bearer token) instead of the separate signed-URL mechanism. (b) A handful of source filenames in the upstream repo contain a literal space (an accidental `"... copy.json"` duplicate) and weren't URL-escaped, so those specific fetches failed outright (`curl` error 3, malformed URL) — fixed with `urllib.parse.quote()` on the filename. Also fixed a related design gap: a single failed file inside an API's sample set used to abort that whole API's fetch (only the directory listing was error-handled, not each file) — each file is now independently try/except'd, so one bad file no longer costs the other 90+ good ones. Final result after both fixes: **43 of 50 cached APIs got real samples, 1,556 files, 0 remaining failures.**

  Also found and fixed a real scope bug in `tools/validate_envelope.py` (0.7) while running it over the whole tree for the first time: it was scanning `knowledge/index/*.md` too, including the static `id-registry.md`, which isn't an artefact envelope at all (per spec.md §5.4, `index/` is generated catalogs, never artefacts themselves) — reported as a false "MISSING frontmatter" failure. Fixed by excluding `knowledge/index/` from the scan regardless of what root is passed. `validate_envelope.py --strict knowledge` now reports **79/79 artefacts clean** (6 use cases + 23 components + 50 APIs).
